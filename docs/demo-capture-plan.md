# Product demonstration capture plan

The current factory-floor images and animation are conceptual illustrations. Real recordings are outstanding; do not simulate proof.

| Recording | Capture | Acceptance criteria |
|---|---|---|
| Issue to PR | Onboard, label issue, run one job, show checks/reviews and PR | Visible operator decision, actual commands and redacted evidence |
| Control room | Start local dashboard, show tabs, jobs, PRs | Actual dashboard; no invented metrics |
| Failure and recovery | Seed a failing check in a disposable project, show rework or escalation | Genuine gate failure, bounded recovery and no policy bypass |

Use a fictional/disposable project and approved model spend. Record source run date, revision, environment and evidence type. Save concise GIFs/screenshots under docs/assets/ when available; provide static alternatives and alt text. Use the [brand standard](brand/brand-system.md). Until then, link to the existing [pilot report](../reference/binley/pilot-report-2026-11-21.md) and test commands.
